# 학습 노트 만들기

형식·구조 규칙은 전부 `CLAUDE.md`(STAR 구조, §5 게시 규칙, §7 체크리스트)를 따른다. 아래 순서대로 해줘.

1. **코드 읽기**: 보통 강의 때 실습한 코드 파일을 준다. 먼저 묻지 말고 코드부터 전부 읽어줘.
   - 패키지·챕터·파일 순서(예: `chap02` → `chap03`, `Application1` → `Application2`)를 학습 흐름으로 보고 STAR를 재구성한다.
     - Situation: 무슨 강의·챕터에서 뭘 실습했는지
     - Task: 앞 단계 코드의 한계 (다음 단계가 왜 필요했는지)
     - Action: 단계별 코드 변화 — 무엇을 바꿨고 왜 바꿨는지
     - Result: 코드 줄 수, 중복 제거, 클래스 분리 등 코드에서 셀 수 있는 변화
   - 주석 처리된 코드, 같은 기능의 여러 버전은 시행착오 근거로 쓴다.
   - 톤은 기존 글처럼 내가 정리하는 일기체("~했다"). 범위는 준 파일 전체.
   - 코드에 없는 경험(어려웠던 점, 실제 에러 등)은 지어내지 마. 임의로 만든 코드는 "예시 코드"라고 적어줘.
2. **초안**: `drafts/YYYY-MM-DD-영문-슬러그.md`에 머리말 포함 완성본으로 써줘.
   - 코드는 내 실습 코드를 그대로 인용하고, 필요한 부분만 잘라서 쓴다.
   - 코드만으로 알 수 없는 부분은 `<!-- TODO: ... -->`로 비워두고 리뷰 때 물어본다.
   - 이미지가 있으면 `posts/assets/<슬러그>/`로 복사하고 본문 경로를 맞춰줘. (슬러그 = 제목의 공백을 `-`로 바꾼 것)
   - API·버전별 동작처럼 확실하지 않은 내용은 공식 문서로 확인하고 참고 자료에 링크해줘.
3. **리뷰**: 초안 경로와 함께 CLAUDE.md §7 체크리스트 결과를 보여줘. 못 채운 항목은 이유를 적어줘.
   - TODO로 남긴 부분은 질문으로 한 번에 묶어서 물어봐줘. (없으면 생략)
4. **게시**: 내가 좋다고 하기 전에는 게시·커밋하지 마. 확인하면:
   - `node publish.js drafts/<파일>.md` 실행 (manifest 등록, 카운트, 이전/다음 글 전부 자동)
   - manifest나 글 HTML을 손으로 고치지 마.
5. 커밋하고 push 해줘. (커밋 메시지: "제목 블로그 본문 작성")
