HTML 폼(Form) 태그 심화와 CSS 선택자 정리

부트캠프 강의에서 HTML 폼(Form) 태그의 다양한 input 타입과, CSS 선택자·속성 선택자로 원하는 요소를 정확히 지정하는 방법을 실습하며 정리했습니다.

2026-09-06

저번 HTML 완전 정복 글에서는 태그를 전체적으로 훑었는데, 그때 폼(Form) 부분은 겉핥기로만 다뤘다. 이번엔 실습을 통해 폼 안에서 쓰이는 다양한 input 타입을 하나하나 뜯어봤고, 처음 배운 CSS로 그 요소들을 원하는 대로 골라 꾸미는 선택자까지 이어서 정리했다.

form 태그의 역할

form 태그는 사용자가 값을 입력할 수 있는 양식을 제공하고, 내부의 input 태그로 입력받은 데이터를 서버로 전달하는 역할을 한다. 구글 폼이나 네이버 로그인 화면처럼, 여러 입력 요소를 자식 태그로 묶어서 하나의 폼으로 만든다.

form 태그의 핵심 속성은 두 가지다.

속성 설명
action 입력된 값들을 전송받을 서버의 주소
method 전송 방식 지정 (get / post)

get과 post의 차이가 특히 중요했다.

방식 데이터 노출 기본값
get url에 데이터가 그대로 보인다 기본값
post url에 데이터가 감춰진다 - 
<form action="search" method="post">
    <label for="">검색 할 내용</label>
    <input type="text" name="search" required>
    <button type="submit">검색!</button>
</form>

텍스트 입력: text, password

가장 기본적인 입력창은 type="text"다.

<input type="text" id="userId" name="userId"
    size="60" placeholder="아이디를 입력해주세요">
  • size 속성으로 입력 칸의 가로 크기를 조절할 수 있다.
  • placeholder 속성으로 무엇을 입력해야 하는지 안내 문구를 넣을 수 있다.

비밀번호처럼 화면에 그대로 노출되면 안 되는 값은 type="password"를 쓴다.

<label>비밀번호 : </label>
<input type="password" name="userPwd" size="40"
    placeholder="비밀번호를 입력해주세요">

숫자와 범위: number, range

<label>수량 : </label>
<input type="number" name="amount" min="0" max="10" value="0" step="3">
<label>점수 : </label>
<input type="range" name="point" min="0" max="100" value="10">

min은 최솟값, max는 최댓값, value는 기본값이다. number는 숫자를 직접 타이핑해 넣는 방식이고, range는 슬라이더로 범위 안의 값을 고르는 방식이라는 차이가 있다.

날짜와 시간

type 선택 범위
date 년/월/일
month 년/월
week 주 단위
time 시:분
datetime-local 년/월/일/시간(로컬 기준) 
<label>date : </label><input type="date" name="date">
<label>month :</label><input type="month" name="month">
<label>week : </label><input type="week" name="week">

라디오 버튼과 체크박스

라디오 버튼은 하나만 선택할 수 있다. 여러 개의 라디오를 하나의 그룹으로 묶으려면 name 속성 값을 반드시 일치시켜야 한다. 일치시키지 않으면 그룹으로 묶이지 않아서 여러 개가 동시에 선택되는 문제가 생긴다.

<label>성별 : </label>
<input id="male" type="radio" name="gender" value="남성">
<label for="male">남성</label>
<input id="female" type="radio" name="gender" value="여성">
<label for="female">여성</label>

체크박스도 name을 일치시키는 건 같지만, 라디오와 다르게 중복 선택이 가능하다는 점이 다르다.

<label>취미 : </label>
<input type="checkbox" id="baseball" name="hobby" value="야구" checked>
<label for="baseball">야구</label>
<input type="checkbox" id="basketball" name="hobby" value="농구">
<label for="basketball">농구</label>

label의 for 속성은 input의 id와, value는 label 텍스트와 일치시켜 주는 게 좋다는 것도 배웠다.

드롭다운 목록: select와 option

여러 옵션 중 하나(또는 여럿)를 고르게 하는 드롭다운 목록이다.

<label>국적 : </label>
<select name="nation">
    <option value="ko">한국</option>
    <option value="ch">중국</option>
    <option value="jp" selected>일본</option>
</select>

size, multiple 속성을 추가하면 여러 줄이 펼쳐진 목록에서 여러 개를 동시에 선택할 수도 있다. 여기서 재미있었던 점은, 화면에는 "한국", "중국" 같은 한글 텍스트가 보이지만 서버로 넘어가거나 개발자가 실제로 다루는 값은 option의 value(ko, ch 같은)라는 것이다.

그 외 input들과 textarea

<label>색상 선택하기 : </label>
<input type="color" name="color">
<label>파일 선택하기 : </label>
<input type="file" name="file" multiple>
<label>보이지 않는 태그 : </label>
<input type="hidden" name="hidden" value="1">

color는 색상 선택기를, file은 파일 첨부(multiple이면 여러 개)를 담당한다. button 태그는 타입을 따로 지정하지 않으면 기본값이 submit이라는 점이 헷갈리기 쉬웠다.

여러 줄을 입력받아야 할 때는 input이 아니라 textarea를 쓴다. input type="text"는 한 줄만 입력할 수 있지만, textarea는 여러 줄을 입력할 수 있고 세로 크기도 조절할 수 있다.

<textarea cols="50" rows="30"></textarea>

CSS로 꾸미기 — 선택자의 기본

HTML이 문서의 내용을 담당한다면, CSS는 디자인을 담당한다. 꾸미고 싶은 요소를 **선택자(selector)**로 지정한 뒤, {} 안에서 스타일을 적어주는 구조다.

li {
    color: blueviolet;
}

/* 아이디 선택자, id는 # 기호로 지정 */
#id3 {
    color: green;
    background: yellow;
}
  • 태그 이름을 그대로 쓰면 태그 선택자
  • #은 id 선택자
  • .은 class 선택자

이렇게 기호로 대응되지 않는 속성은 대괄호([])를 쓰는 속성 선택자로 지정할 수 있다는 것도 배웠다. 그리고 스타일이 여러 개 겹치면 우선순위에 따라 적용된다는 점도 함께 익혔다.

외부 스타일시트로 분리하기

html 파일 안에 css를 직접 적는 대신, .css 파일을 따로 만들고 head에서 link 태그로 연결하는 방식도 배웠다.

<head>
    <meta charset="UTF-8">
    <title>Document</title>
    <link rel="stylesheet" href="selector.css">
</head>

디자인이 복잡해질수록 이렇게 분리해두는 게 관리하기 편하겠다는 생각이 들었다.

속성 선택자 (Attribute Selector)

가장 헷갈리면서도 재미있었던 부분이다. 아래와 같은 div들이 있다고 할 때,

<div name="name1 name5 name6" class="div-class">div1</div>
<div name="name2" class="div-class">div2</div>
<div name="name3" class="div-class">div3</div>
<div name="name4 name1" class="div-class">div4</div>

다섯 가지 기호가 각각 다르게 동작한다.

기호 의미 예시
~= 공백으로 구분된 값 중 하나로 완전히 일치하면 선택 div[name~=name1]
|= 값이 정확히 일치하거나, 그 값 뒤에 -가 붙은 문자로 시작하면 선택 `div[class
^= 값을 접두사로 가지고 있으면 선택 div[name^=name]
$= 값을 접미사로 가지고 있으면 선택 div[class$=class]
*= 값 안에 특정 문자열이 포함되어 있으면 선택 div[class*=div] 
div[name~=name1]{
    background: yellow;
}

div[class|=class] {
    background: chartreuse;
    /* class 또는 class-로 시작하는 값을 선택 */
}

div[name^=name] {
    background: blueviolet;
}

div[class$=class] {
    background: white;
}

div[class*=div] {
    background: orchid;
}

~=와 ^=의 차이가 처음엔 헷갈렸다. ~=는 공백으로 나뉜 여러 값 중 정확히 일치하는 값이 있는지를 보는 거고, ^=는 값의 앞부분 글자가 일치하는지를 보는 거라서, 동작 방식 자체가 다르다는 걸 직접 코드를 돌려보고서야 확실히 이해했다.

정리하며

Before: input은 type="text" 정도만 알고 있었고, CSS는 태그/아이디/클래스 선택자만 쓸 줄 알았다.

After: input의 타입에 따라 number, range, date류, radio, checkbox, select, color, file, hidden 등 목적에 맞는 입력 방식을 고를 수 있게 됐고, CSS 속성 선택자 다섯 가지의 차이를 구분해서 쓸 수 있게 됐다.

더 학습하면 좋은 개념

  • 폼 유효성 검사 (Constraint Validation API) — required 외에도 pattern, minlength, maxlength 등으로 서버에 보내기 전에 브라우저 단에서 값을 검증할 수 있다. 폼을 실제 서비스에 쓰려면 꼭 필요한 개념이다.
  • CSS 우선순위(Specificity)와 캐스케이딩 — 같은 요소에 여러 선택자가 겹칠 때 어떤 스타일이 최종 적용되는지 결정하는 규칙이다. id, class, 태그 선택자를 함께 쓰다 보면 반드시 부딪히는 문제다.
  • 가상 클래스/가상 요소 (:hover, ::before 등) — 상태나 위치를 기준으로 요소를 선택하는 CSS 문법이다. 지금 배운 속성 선택자와 함께 알아두면 선택의 폭이 훨씬 넓어진다.
  • 폼 데이터와 서버 통신(GET/POST 실전) — action/method로 배운 개념이 실제로 서버에서 어떻게 요청을 받아 처리하는지 이어서 배우면 폼의 전체 흐름이 이해된다.
  • 접근성 있는 폼 설계 — label의 for 속성, aria 속성 등으로 스크린 리더 사용자도 폼을 문제없이 쓸 수 있게 만드는 방법이다.
